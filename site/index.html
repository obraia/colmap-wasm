Unofficial WebAssembly build of COLMAP 4.2.1

COLMAP, running in your browser.

Camera poses and a sparse point cloud from your photos or video, computed by COLMAP's own SIFT and global mapper compiled to WebAssembly, with SIFT matching on the GPU. Nothing is uploaded: it all runs on this page.

Try it with your frames Source on GitHub npm i colmap-wasm

Built for Gausify Orbit, which turns orbit videos into 3D Gaussian Splats in the browser.

Demo

Drop a video or a set of frames of the same size. A video is sampled into evenly spaced frames. Or generate a synthetic orbit to see it work right away.

This browser has no WebGPU, which the SIFT matching needs. Try a recent Chrome, Edge or Safari.

How it works

          
The same pipeline as colmap feature_extractor → matches_importer → geometric_verifier → view_graph_calibrator → global_mapper, split across the browser's threads and GPU.

        

        

          
SIFT extractionCOLMAP's CPU SIFT (VLFeat)Web Workers · wasm

          
→

          
SIFT matchingbrute force, ratio + cross-checkWebGPU compute

          
→

          
VerificationF / E / H RANSAC per pairWorker · wasm

          
→

          
View-graph calibrationfocal from the pairsWorker · wasm

          
→

          
Global mapperrotation averaging, global positioning, bundle adjustmentWorker · wasm · Ceres

        


        

          

            
What was compiled

            

              Only the parts of COLMAP 4.2.1 this pipeline needs: util, math, geometry,
              sensor, scene, optim, estimators, sfm,
              feature and the global pipeline controller, built with Emscripten for wasm32, single-threaded.
            

            

              Dependencies built the same way: Eigen 3.4, Ceres 2.2 with Eigen's sparse solvers (no SuiteSparse), glog,
              PoseLib and SQLite (an in-memory database, as COLMAP expects one). The module is 7 MB, 2.1 MB gzipped.
            

          

          

            
What had to change

            
    
              
  • No CHOLMOD: Eigen's SimplicialLLT takes SuiteSparse's place in the rotation averaging.
    • 
              
  • No threads: COLMAP's ThreadPool runs each task when it is added; parallelism comes from Web Workers instead.
    • 
              
  • No OpenMP (a single-thread omp.h), no OpenImageIO (the browser decodes images), no faiss (matching moved to the GPU).
    • 
              
  • A small C API that the worker calls: extract one image, or map a whole set.
    • 
            

          

          

            
Matching on the GPU

            

              COLMAP's exact CPU matcher takes minutes for a hundred frames on one thread. The WebGPU shader follows the
              same rule: integer dot products between the uint8 descriptors, the strictly larger one wins in index order,
              then the angle (0.7) and ratio (0.8) tests in float32 and the cross-check. Same matches, in seconds.
            

          

        

      


      

        

          
Does it give COLMAP's answer?

          
Compared with a native COLMAP 4.2.1 on the same images:

        

        

          
StageAgreement

          
            
SIFT keypointswithin ~1e-5 px; descriptors identical

            
Matches (WebGPU)identical to cpu_brute_force_matcher, pair by pair

            
Geometric verificationidentical with the same seed

            
Global mappersame intermediate counts; poses equal up to floating point

          
        

        

          Natively, view_graph_calibrator runs unseeded on several threads, so two native runs on the same input can
          differ slightly. Here every stage is seeded: the same images always give the same cameras.
        

        

          
~20 sSIFT, 90 frames of 1024×1280, 5 workers

          
~5 smatching 900 pairs on the GPU

          
~45 sverification, calibration and global mapper

        

        
Apple M4, Chrome. Peak memory is a few hundred MB per SIFT worker.

      


      

        

          
Use it in your app

        

        
npm install colmap-wasm

        
import { estimatePoses, sequentialPairs, toColmapBinary } from "colmap-wasm";

const { reconstruction, features } = await estimatePoses(files, {
  pairs: sequentialPairs(files.length, { window: 8, loop: true }),
  onProgress: ({ stage, done, total }) => console.log(stage, done, total),
});

// cameras.bin, images.bin, points3D.bin for any COLMAP-compatible tool
const sparse = toColmapBinary(reconstruction, features);

        

          The API, build instructions and the patches are in the
          repository. With Vite, add
          optimizeDeps: { exclude: ["colmap-wasm"] }.
